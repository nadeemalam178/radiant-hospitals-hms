5 Single-Port Embedded Distribution Architecture
The Distribution Package radiant-hms-v1.0.0.zip
The application is supplied as a self-contained, pre-compiled ZIP archive. It contains:
  • Frontend Pre-compiled Assets: Optimized static bundle in frontend/dist/.
  • Backend Compiled Runtime: Express engine in backend/dist/.
  • 1-Click Batch Utilities: Installation, launch, firewall, and backup scripts.
Single-Port (Port 4000) Advantage Zero Maintenance
Unlike legacy systems requiring complex Apache or IIS configurations:
  • One Network Port: Node.js serves both the web interface and REST APIs on Port 4000.
  • Zero Workstation Setup: Works immediately in any browser via http://[Server-IP]:4000.
  • Minimal Attack Surface: Only Port 4000 is open on the hospital server firewall.

7 Three-Step Automated Windows Deployment Protocol
Step 1
Extract Archive
Extract radiant-hms-v1.0.0.zip directly into C:\RadiantHMS\ on the designated server PC.
Step 2
1-Click Initialization
Right-click scripts\install-windows.bat → Run as Administrator. Automatically initializes all 32 relational tables.
Step 3
Firewall & Launch
Run setup-firewall.bat once, then double-click start-hms.bat. System launches and displays the Setup Wizard at localhost:4000.
8 Automated Backup & 10-Minute Disaster Recovery Policy
Automated Nightly Backups (2:00 AM) Scheduled
• Windows Task Scheduler runs scripts\backup-db.bat every night automatically.
• Creates a timestamped, compressed .sql archive in C:\RadiantHMS\backups\.
• Built-in 30-day retention automatically removes obsolete files to prevent disk overflow.
• Best Practice: Hospital IT attaches a secondary external USB drive for weekly offsite mirroring.
10-Minute Emergency System Recovery Disaster Ready
• If the server PC ever experiences total hardware failure:
• Copy the latest backup snapshot to any spare Windows laptop or PC.
• Run scripts\restore-db.bat, specify the backup file, and type RESTORE.
• All patient charts, active ward beds, invoices, and audit histories are restored with zero data corruption.
9 Hospital IT & Management Frequently Asked Questions
What happens if our hospital's internet connection goes down?
Operations continue completely uninterrupted. Radiant HMS does not require external cloud servers, third-party CDNs, or internet access to function. All records, billing, and registrations occur over the hospital's local network.
Do we need to install software on doctors' laptops, reception desks, or tablets?
No software is installed on client workstations. Staff simply open their web browser (Google Chrome, Microsoft Edge, Safari) and navigate to the hospital server's local address (e.g., http://192.168.1.11:4000).
How does the system ensure patient data privacy and prevent leaks?
The database is bound exclusively to the server's internal localhost and is never directly accessible over the network. Passwords use 12-round salted hashing, permissions are strictly checked by server middleware, and an immutable audit log records all sensitive modifications.
Can we connect mobile apps or medical diagnostic machines in the future?
Yes. Radiant HMS is built around standard RESTful JSON APIs and Swagger documentation. Mobile applications (iOS/Android) and laboratory equipment can integrate directly with existing endpoints without changing the backend.
